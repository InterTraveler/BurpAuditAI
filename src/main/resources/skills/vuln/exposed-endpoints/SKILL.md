本技能专注于"无需授权或仅弱授权的管理 / 调试 / 监控 / 内部接口被发现"的风险。这是渗透第一波"暴露面收敛"的常见产出。在你识别到疑似暴露端点时，按以下流程处理：
1. 识别暴露面来源（按权重排）：
   - URL 直命中：/actuator/* (Spring)、/swagger-ui.html、/api-docs/swagger.json、/v2/api-docs、/v3/api-docs、/nacos、/apollo/...、/grafana、/kibana、/jenkins、/airflow、/prometheus、/metrics、/health、/info、/h2-console、/phpmyadmin、/wp-admin、/wp-login.php、/solr、/_cat、/_cluster、/_nodes、/api/v1/namespaces (k8s)、/v1.39/containers/json (docker)、/api/now/table (ServiceNow)、/api/edgescripts、/api/experiments、/__admin、/debug、/trace、/heapdump、/env、/beans、/mappings、/jolokia、/console、/internal、/private、/manage。
   - 响应头指纹：X-Application-Context (Spring)、Server: Tengine / JBoss-EAP / WildFly / Jetty / nginx-OpenShift / Apollo；X-Powered-By: Phusion / Express。
   - JS bundle / 静态资源：swagger-ui-bundle.js、apollo-client、actuator、grafana、swagger、redoc、rap。
   - HTML 注释：<!-- generated by swagger -->、<!-- for apollo -->。
2. 判断"是否能直接访问"：
   - 主动鉴权结果：去掉 Authorization / Cookie 直接重放该 URL，看是否仍 200 + 返回敏感内容。
   - 默认凭证：很多内置组件有默认账密（admin/admin、apollo/admin、nacos/nacos、jenkins/jenkins、kibana/elastic），看响应里是否提示登录页 + 默认用户名。
   - 注册开放：Nacos 默认开启匿名访问 + 注册中心；Apollo Config Service / Admin 默认无需鉴权。
3. 评估暴露后的危害面：
   - /actuator/env：dump 所有环境变量（含数据库密码、AK/SK）→ critical；
   - /actuator/heapdump：JVM 堆 dump，可解析出内存里的密码、token → critical；
   - /actuator/beans + /mappings：拿到完整路由表 + Bean → 给攻击者完整攻击面地图；
   - /jolokia：通过 JMX 远程执行 MBean → RCE；
   - Swagger UI + 未鉴权：完整 API 文档 + 在线调试 → 找高价值接口直接调用；
   - /metrics、/actuator/prometheus：监控指标，泄漏业务量 / 内部地址；
   - /h2-console + Spring Boot：H2 数据库 console + 默认 JDBC URL = 直接 SQL 执行；
   - Kibana / Elasticsearch：未授权 _search、_cat/indices → 数据泄漏；
   - Docker API / Kubernetes API：未授权 = 容器逃逸 / 集群接管；
   - Jenkins：未授权 = 凭证泄漏 + RCE（脚本控制台）；
   - Nacos / Apollo / Consul：服务发现 + 配置中心 = 拿到所有下游服务配置（含数据库、Redis、MQS）。
4. 给出修复建议：内网管理端点强制只 listen 内网 IP 或 Unix socket；用 Spring Security / Shiro 等做强制鉴权；关掉 Spring Boot Actuator 暴露（management.endpoints.web.exposure.include=health）；/swagger-ui 只在 pre-prod 启用 + 加 Basic Auth；Nacos / Apollo / Consul 默认开启鉴权 + 改默认密码；Kibana 加 xpack.security.enabled；Docker API 加 TLS + 客户端证书；Jenkins 启用 Security Realm；H2 console 默认 production 关闭。
所有由本技能产出的 finding 必须设置 type=exposed-endpoints。多个技能可能同时被激活，本技能不负责 Spring Boot 框架版本本身的 CVE（那是 techstack-nday）/ 暴露的接口本身的业务漏洞（暴露后再让 sql-injection / auth-bypass 接手深入）。
【重放建议】暴露面类问题重放有 3 次硬上限（orchestrator 管控），按：
- 第 1 次：去掉 Authorization / Cookie / 所有自定义头，直接访问该 URL，看是否 200 + 返回敏感内容；
- 第 2 次：如果 401 / 403，看响应头是否泄漏框架版本（Server / X-Powered-By）→ 给低危 + 提示"框架指纹暴露"；
- 第 3 次（精调）：试默认凭证（admin/admin、apollo/admin、nacos/nacos、admin/123456、jenkins 默认无密），看能否进管理面板。
直接拿到敏感内容（env / heapdump / 配置中心数据）= critical；仅拿到登录页 + 默认账密提示 = high；仅框架指纹 = low。本技能是"分析建议"而非"硬性规则"，最终判断权交给模型。
- 【反误报】给 finding 设 confidence 时，只在能解释清楚"为什么 ≥ 60" 时给 ≥60；判不成立 / 仅残留小概率不确定性（如 5%–20%）的疑似不要写进 findings——本插件解析阶段会再过一道阈值（约 30）兜底，但 prompt 层的克制才是从源头减少问题列表噪声 finding 的关键。
